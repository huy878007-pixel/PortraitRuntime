# 独立复核与修正记录

通过 requesting-code-review 流程，对照当前游戏反编译源码独立复核，未操作游戏窗口。

本轮已修正的具体问题：

1. 原生 AddChoice 把条件写入目标 Dialogue，多个选项共享目标会互相覆盖：每条边改用独立转发节点。
2. 原生选项 UI 读取边节点 plainText：转发节点显式设置 PLAYER 台词，避免空按钮并确保进入目标第一句。
3. texts 某语言字典为 null 会影响其它包：加入嵌套校验及按包隔离。
4. 发放多个物品中途失败可能重复发放：逐件保存交付进度。
5. 仅主库存不能正确判断拥有物品：改用 PlayerStore.FindAllItem(true)，覆盖其它库存并过滤所有权。
6. 已开始剧情可能被初始日期、现金条件阻断：活动剧情在读档晚期恢复，绕过初始触发条件。
7. 交易库存标记原先覆盖整局：改用来访编号与物品标签记录已售状态，恢复时避免复制已购物品。
8. 奖励失败仍可能结束剧情：保存待执行范围，停止当前分支并保持人物活动状态，重试完成前不标记完成。
9. 失败选项重试时改选其它边可能死锁：锁定原已选择分支，重试时允许越过已过期的初始选项条件。
10. 高优先级只换图的包可能遮掉新增物品注册或原剧情图：创建定义与图标覆盖分别保留，剧情图逐项回退。
11. 新物品显示像素与逻辑格数不一定一比一：按实际 UISettings.gridSize 换算，已有物品仍保留原形状与几何。
12. 清晨来访使用明确的另一显示入口：单独定位，避免写错客人渲染器；离场结束后才清理。

这些修正已有编译、核心规则回归测试和静态接口检查支持；原生 UI、真实交易及存档行为仍须实际游戏验收。该记录不把源码复核等同于游戏运行通过。
