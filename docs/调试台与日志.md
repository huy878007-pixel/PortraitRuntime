# 核心调试台与详细日志

0.3.1 分为两个 Mod：核心 `player.portraitruntime` 不带美术，人物美化内容版 `player.launchgiftportraits` 依赖核心。旧独立美化版必须先备份到 Mods 目录外，再安装同 ID 的新内容版。可单独运行核心。

## 当天巡检

游戏窗口由你操作；以下功能已构建、自动验证，实际游戏显示和流程仍待验收。

1. 使用独立测试存档，开店营业，先完成当前客人并等待离场动画结束。
2. F3 打开调试台；界面可切换并保存 F4。F10 保留显示设置，F11 导出诊断。
3. “当天全部人物巡览”包含 276 个原版来访注册项、美化角色配置阶段及当前游戏精灵池。也可分别巡检角色阶段、669 条剧情配图、随机池精灵，或搜索单项。
4. 支持上一位、重看、下一位、暂停、每 4 秒自动播放，填写备注后“标记异常并下一位”，导出巡检报告。关闭大窗口仍有控制条；“结束巡览”恢复原排队。

默认外观预览使用原生来访和显示流程，不运行原版剧情工厂及剧情回调。原版注册中的随机外观会选择可解析的精灵，完整外观另用精灵池巡检。预览不能证明原剧情分支执行正确。

巡检期间阻止保存，存档或日期变化会取消巡检。这不是完整游戏状态回滚。高级真实来访必须显式勾选，会执行原工厂，可能改变剧情、金钱或结束游戏，只用于独立测试存档。

## 日志与报告

详细日志默认开启，可在调试台切换并保存。JSONL 每行含 UTC 时间、会话 ID、递增序号、级别、事件名；运行时事件附带帧号和日期。记录：

- 内容源注册、包校验、依赖和冲突。
- 人物身份、工厂、台词 key、匹配结果及使用的资源。
- 资源加载和释放、剧情动作开始/完成/待执行。
- 巡检范围、进度、结果、备注和完整异常堆栈。

相同异常在 5 秒内合并，后续异常记录附带合并数量。关闭详细模式仍记录信息、警告和错误。

目录为 `Application.persistentDataPath/PortraitRuntime/logs`，本机通常是：

`%USERPROFILE%\AppData\LocalLow\Questing Goose Studio\Probably Stolen\PortraitRuntime\logs`

日志不写入受信任 Mod 目录。每会话单文件最多 4 MiB、最多 32 个文件；超大事件或容量超限计入 Dropped，诊断报告可见。历史会话保留，可在退出游戏后自行归档。文件日志不可写时记录 Failure 并降级运行，初始化警告同时写入游戏 Player.log。

F11 诊断、调试台巡检报告也写到该目录。反馈问题时提供复现步骤、本轮 runtime JSONL、diagnostics JSON、巡检报告；必要时附 Player.log 中 `[PortraitRuntime]` 附近内容，无需上传整个存档。

0.2.2：默认调试键改为 F3，可改 F4；旧 F7/F8 配置自动回退 F3。游戏右上角有 Debug 按钮入口。日志新增 pump.update.started、pump.gui.started、30 秒心跳及 debug.toggle，并记录立绘位置、缩放、边界、颜色和 shader。默认显示设置不接管原生位置与缩放，自定义调整只在人物停止移动后应用。

0.3.0：显示设置与 F10 窗口迁到人物美化内容包，核心不再绘制任何设置界面，`ui.json` 改存到美化 DLL 同目录（旧核心目录的 `ui.json` 首次启用时读取一次并备份为 `ui.json.core-legacy.bak`）。核心自身的缓存、调试键与日志开关改存 `runtime.json`。巡检取图改用游戏自己的规则：查不到 key 时按原生回退随机拾荒者并标记「待核对」，不再借用字典第一张图；日志新增 `debug.sprite.resolved`，`debug.sprite.fallback` 增加 `status` 与 `expressions`。生命周期新增 `client.before-arrival`、`client.leaving`、`client.outside`、`scene.loaded` 节点，柜台外博士与朝左／朝右离场现在都有对应处理。

0.3.1：核心不再替换任何图片。`SpriteDict.GetSprite`、`RenderHandler.LoadFromFile` 与物品图标的钩子只把原生名字交给美化包注册的 resolver，返回空就保持原版；特殊资源（通缉令、通缉头像、`drjackson2`）的场景替换与 `special_targets.json` 整体迁到美化包，核心发布包不再带该文件。接口升到 `Version=2`，新增 `SetSpriteResolver`、`SetItemResolver`、`ApplyTo`、`ReleaseTo` 与 `assets/1` 能力。

0.3.2：更正上一条的边界。物品图标本来就属于核心的物品运行时（`items[].icon` 是内容包声明，美化包自己没有任何物品），已从美化包收回，`SetItemResolver` 与 `assets/1` 中的物品分支一并删除；`Lookup` 的场景资源查询简化为 `{key}`。核心继续不碰人物与场景美术。

0.3.3：修复美化包在核心之前加载时绑定失败的问题——原生加载器不按 Prerequisites 排序，原先 `OnEnable` 找不到核心就永久放弃，导致立绘、F10、特殊资源全部消失。现在帧驱动会重试绑定，成功后调 `Sync()` 补播当前客人。

0.3.4：取图改为按原生精灵名即时替换（与 1.2.5 的实际机制一致），不再只等人站到柜台才换。`SpriteDict.GetSprite` 与 `RenderHandler.LoadFromFile` 把名字交给美化包的 resolver，核心按「特殊资源 → 角色 variants」解析；只替换角色自己声明的名字，共享的通用精灵（`maleScav5`、`sec` 等）保持原版，同名被两个角色声明时拒绝猜测。离场事件改用 `StoreUIManager.OnClientStartLeaving`（1.2.5 用的就是它），左右方向从参数取。
