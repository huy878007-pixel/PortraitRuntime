# 实施约定

用户已确认：核心库支持原版内容管理与覆盖，也支持新增人物、剧情分支、物品、触发条件和随游戏存档持久化。现有娘化内容作为首个核心包。先交付可构建与自动测试版本，游戏窗口由用户操作。

开发基线：BuildID 26337366；Assembly-CSharp.dll SHA256 6398d44aa1675e1f02b63bc668868f970e0f5d3ae5a50f2aced8d06ca084e3b5。数据来自桌面核心库数据审计_20261101_163648。

实现采用：纯 C# Core（数据包解析、校验、身份与优先级、条件和动作）、原生 IMod Unity Adapter（游戏生命周期、显示、注册、存档）、CLI（校验与模拟）、Python 迁移与打包、离线中文工作台。

先完成核心规则的自动测试，再接游戏接口；然后迁移现有内容和新增示范；最后生成发布包、文档与验收入口。各阶段均以实际构建及测试输出记录，不把自动模拟等同于游戏内运行。

内容 ID 区分包、角色定义、游戏 identifier、工厂来源、物品 ID、剧情节点。默认 NO_ID 无法作为身份。角色通过明确身份或创建工厂匹配；精灵 key 仅用于同角色不同阶段选图。物品外观覆盖在具体物品解析层进行，不修改 BuildShapeFromSprite。

存档优先接入原生 ModData；新增物品读档前注册。缺失内容包时保留状态，记录缺失内容，不静默抹除。数据包不执行任意脚本；复杂行为通过受信任 C# 扩展接口提供。

性能目标：按需加载，缓存按字节预算淘汰，无每帧全场景扫描。稳定性目标：坏包隔离；缺图回退；未知游戏程序集默认禁用游戏钩子，工具仍可使用。文件只从包根目录内读取。离线使用，不上传资源或存档。

发布验收包含：旧串图案例、同文本剧情、离场显示、新人物触发、分支结果、新物品库存与交易、保存读档、缺包和多包冲突、设置开关。游戏内验收须用户执行并提交诊断日志，开发过程不操作用户游戏窗口。
